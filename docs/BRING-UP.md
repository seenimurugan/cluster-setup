# Bring-up Runbook — Standing up the full homelab stack on a new machine

This runbook covers everything needed to replicate the homelab on a fresh Mac.
Work through sections in order; steps marked **[admin-console]** are manual
one-time steps in the Tailscale web UI, not automatable.

---

## Prerequisites — admin-console / out-of-repo steps

These must be completed **before** deploying any app. They live in the Tailscale
admin console and cannot be scripted from within the cluster.

### 1. OAuth client + tag setup

Admin console → **Settings** → **OAuth clients** → **Generate OAuth client**:
- Scopes: `devices`, `auth_keys`
- Assign tag: `tag:k8s-operator` (this tag owns `tag:k8s`)

Save the client ID + secret — they go into the tailscale-operator Secret during deploy.

### 2. ACL funnel grant

Admin console → **Access Controls** → add to the `nodeAttrs` array:

```json
{"target": ["tag:k8s", "autogroup:member"], "attr": ["funnel"]}
```

Without `tag:k8s` in the target, the operator's proxy pods (which are tagged
`tag:k8s`, not `autogroup:member`) silently fail to enable Funnel.

### 3. Enable HTTPS Certificates + MagicDNS

Admin console → **DNS**:
- Enable **MagicDNS** (needed for `<host>.stoat-perch.ts.net` to resolve)
- Enable **HTTPS Certificates** (needed for trusted TLS on Funnel URLs)

### 4. Immich External Domain

After deploying Immich and `public-inject-proxy`, set the external domain in
Immich admin settings:

- Immich UI → **Administration** → **Settings** → **Server** → **External Domain**
- Set to: `https://seeni-photos.stoat-perch.ts.net`

This ensures Immich embeds the correct public hostname in shared album links.

### 5. Umami admin password

Umami enforces a minimum password length of 8 characters via its UI and API.
The homelab default (admin/admin, 5 chars) must be set via direct DB update.
See `umami/docs/MAINTENANCE.md` → "Change admin password".

## .env files

Every app repo carries `.env.example`. On a new machine:

```bash
cp .env.example .env
# Fill in secrets: DB passwords, JWT secrets, Umami APP_SECRET, etc.
```

Key `.env` vars per app:

| App | Key vars |
|-----|----------|
| `shared-postgres` | `POSTGRES_PASSWORD` |
| `umami` | `APP_SECRET`, `DATABASE_URL` |
| `chores` | `CHORES_ADMIN_PASSWORD`, `CHORES_JWT_SECRET`, `DB_PASSWORD` |
| `public-inject-proxy` | `UMAMI_SEENI_PHOTOS_ID`, `UMAMI_SEENI_CHORES_ID` (see step 4 of deploy order below) |

## Deploy order

Apps have dependencies — deploy in this numbered order.

### 1. cluster-setup (+ Tailscale operator + ingress class)

```bash
cd /path/to/apps/cluster-setup
cp .env.example .env  # fill TAILSCALE_OAUTH_CLIENT_ID + TAILSCALE_OAUTH_CLIENT_SECRET
./deploy.sh
```

This installs:
- OrbStack k3s cluster (if not already running)
- Tailscale operator (namespace `tailscale`)
- Ingress class `tailscale`
- `homelab` namespace

### 2. shared-postgres

```bash
cd /path/to/apps/shared-postgres
cp .env.example .env  # fill POSTGRES_PASSWORD
./deploy.sh
```

All custom apps (chores, umami, reminders, etc.) share this instance.

### 3. App layer (any order — these are independent of each other)

```bash
cd /path/to/apps/umami          && cp .env.example .env && ./deploy.sh
cd /path/to/apps/immich-public-proxy && cp .env.example .env && ./deploy.sh
cd /path/to/apps/chores         && cp .env.example .env && ./deploy.sh
```

Other apps (reminders, storage-console, moviesda, etc.) can also be deployed here.

### 4. Umami website-id wiring (required before public-inject-proxy)

`public-inject-proxy` injects a per-site Umami tracking ID into HTML. These IDs
are generated by Umami after website registration — they cannot be pre-configured.

1. Open `https://umami.stoat-perch.ts.net` (tailnet-only)
2. Log in → **Settings** → **Websites** → **Add website**
   - Add `seeni-photos` (domain: `seeni-photos.stoat-perch.ts.net`)
   - Add `seeni-chores` (domain: `seeni-chores.stoat-perch.ts.net`)
3. Copy each website's **Website ID** (UUID shown in website settings)
4. Edit `public-inject-proxy/.env`:
   ```
   UMAMI_SEENI_PHOTOS_ID=<uuid from step 3>
   UMAMI_SEENI_CHORES_ID=<uuid from step 3>
   ```

### 5. public-inject-proxy (LAST — depends on backends + Umami website-ids)

```bash
cd /path/to/apps/public-inject-proxy
cp .env.example .env   # fill UMAMI_SEENI_PHOTOS_ID + UMAMI_SEENI_CHORES_ID (from step 4)
./deploy.sh
```

This deploys the nginx proxy that:
- Routes `seeni-photos.*` → `immich-public-proxy`
- Routes `seeni-chores.*` → `chores-frontend` / `chores-backend`
- Injects Umami `<script>` into HTML responses on both public paths
- Serves `/_umami/script.js` and `/_umami/api/send` (collection endpoints)
- Blocks all other `/_umami/*` paths (admin UI stays private)

## Verification checklist

After all apps are deployed:

```bash
# Cluster health
kubectl get pods -A | grep -v Running | grep -v Completed

# Funnel endpoints reachable (from off-tailnet device)
curl -I https://seeni-photos.stoat-perch.ts.net
curl -I https://seeni-chores.stoat-perch.ts.net

# Umami script injected in HTML
curl -s https://seeni-chores.stoat-perch.ts.net | grep umami

# Umami collection endpoint reachable
curl -I https://seeni-chores.stoat-perch.ts.net/_umami/script.js

# Umami dashboard NOT public (must get 404/refused from off-tailnet)
curl -I https://umami.stoat-perch.ts.net  # should fail off-tailnet
```
